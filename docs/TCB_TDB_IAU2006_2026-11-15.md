# Split-JD TCB to TDB conversion

The Rust core's `tcb_tdb::tcb_to_tdb` applies the linear definition in
[IAU 2006 Resolution B3](https://www.iau.org/static/resolutions/IAU2006_Resol3.pdf):
TDB is obtained from TCB using the specified epoch, scale factor and fixed
offset. Inputs and outputs are two Julian-date parts; the larger input part
is preserved and the correction applied to the smaller. Either part order is
accepted. The supported TCB JD range is explicitly limited to 2400000–2600000;
nonfinite or implausibly large parts are rejected. This relation does not
convert UTC, UT1, TT, leap seconds or civil time.

Independent reference tests use pyerfa 2.0.1.5 `tcbtdb` for J2000, J2016 and
a split fractional epoch, including swapped parts. At J2016.0 TCB,
TDB−TCB is approximately **−19.0826963147 seconds**. The split result avoids
adding the correction directly to a large JD, but callers that collapse it to
one binary64 JD lose precision; the current star CLI does so and has roughly
40 microseconds of JD granularity near the present. This conversion does not
independently validate the time scale assigned to an external catalog epoch.
