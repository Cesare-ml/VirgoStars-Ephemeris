# Classic JPL DE441 reader

The experimental Rust core reads the classic little-endian JPL DE441 binary,
including the `de441.eph` file distributed with Astrodienst's JPL files. It
does not read Astrodienst's compressed `.se1` files or NAIF SPK (`.bsp`)
kernels. Supply the data file separately; no ephemeris data is bundled.

```rust
use virgostars_ephemeris_core::de441::{Body, De441, JulianDateTdb};

let mut ephemeris = De441::open("/path/to/de441.eph")?;
let state = ephemeris.state(
    Body::Moon,
    Body::Earth,
    JulianDateTdb(2451545.0),
)?;
println!("{:?}", state.position_km);
# Ok::<(), Box<dyn std::error::Error>>(())
```

`De441::new` also accepts any `Read + Seek` input, including an in-memory
`Cursor`; `De441::open` reads file records on demand without loading the full
2.8 GB file. A caller can select any supported target and center. Dates must be
Julian dates on the **TDB** time scale, not UTC. Returned position and velocity
are geometric, in equatorial ICRF axes, in km and km/day respectively.
Outer-planet series represent system barycenters rather than planetary centers.

## Sampling several targets at the same epoch

For an interactive chart or a future language binding, use the batch method
`states_at(targets, center, tdb_epoch)` to request several **geometric ICRF**
states without repeatedly crossing the API boundary. For example:

```rust
let targets = [Body::Sun, Body::Moon, Body::Mercury, Body::Venus];
let states = ephemeris.states_at(
    &targets,
    Body::Earth,
    JulianDateTdb(2451545.0),
)?;
assert_eq!(states.len(), targets.len());
```

This is a convenience interface over the existing scalar `state()` routine
and its one-record cache; it is **not** a new interpolation algorithm.
Results are returned in request order (duplicates preserved). All states
use the same TDB epoch and center, with positions in km and velocities in
km/day. An empty list returns an empty result after validating coverage but
without reading a coefficient record. Any missing series, corrupt record or
I/O failure rejects the **whole** call; no partial successful result is
returned. Storage is proportional to the requested target count, so clients
should keep the input bounded. All existing limitations (including missing
planet-center series) apply; no apparent, true-of-date or zodiac coordinates
are generated.

The deterministic synthetic record-cache tests check scalar/batch numerical
identity, ordering, duplicate requests, one-record I/O reuse and failure
handling. They do **not** demonstrate real-kernel JPL/Horizons agreement or
measured end-to-end UI performance.

Modification (2026-11-11): original Rust batch interface, integration tests
and documentation added. No external datasets, runtime dependencies, or
licensing changes.

`coverage()` reports the inclusive interval from the binary header. The local
DE441 file inspected on 2026-11-09 covers JD -3027215.5 to 7930192.5; those
binary values take precedence over the file's human-readable title. This
reader does not convert civil time, apply light-time, aberration, deflection,
precession, nutation or topocentric corrections, or compute zodiac positions.
It is not a complete astrological ephemeris API.

## Read-only local file coverage inspector (experimental)

For a **locally supplied classic binary** DE441 file, run:

```bash
cargo run --offline --locked --example inspect_classic_de441 -- /path/to/de441.eph
```

On success, stdout is exactly two CSV lines with the format identifier and
**inclusive start/end TDB Julian dates declared by the binary header**:

```csv
format,coverage_start_jd_tdb,coverage_end_jd_tdb
classic-de441,1000,1032
```

The numbers above are from a **synthetic test file**, not an official JPL
kernel. The command checks the classic DE441 header and file length through
`De441::new`; it does **not** read/evaluate every polynomial record,
authenticate the kernel, calculate sky positions or prove agreement with
NAIF/JPL Horizons. No external data are downloaded or bundled. Missing,
short, wrong-format or inconsistent-length files fail with a nonzero exit
code and no partial CSV output. Do not run this on NAIF `.bsp` kernels.

CLI/parser regression tests (including synthetic one-record validation):

```bash
cargo test --offline --locked --example inspect_classic_de441
```

Run `cargo test --workspace`. To exercise the external file too, set
`DE441_PATH` to its path and run `cargo test --workspace -- --ignored`.
Tests check analytical polynomials, velocities,
boundaries, Earth/Moon reconstruction, invalid files and local-file regression.
The reader rejects non-finite Chebyshev coefficients and non-finite evaluated
positions or velocities with `De441Error::InvalidFile`, rather than returning
NaN/Infinity states from damaged input records.
The regression values were produced by the earlier JavaScript prototype, so
they are not an independent scientific reference. Comparison with JPL
reference vectors is still needed before claiming numerical accuracy or
production readiness.

## Untrusted file resource limit

Modification recorded 2026-11-14: the classic reader refuses header pointer
layouts requiring a coefficient-record cache larger than **16 MiB**, before
allocating that buffer. The header's pointer indexes are untrusted even when a
seekable stream advertises a matching, potentially sparse file length. This
generous implementation safety cap is not a JPL specification limit and does
not authenticate a kernel; unusually structured third-party files may be
rejected. A normal classic DE441 record remains supported. The reader still
loads only one bounded coefficient record at a time.

Sources: [JPL ephemeris formats](https://ssd.jpl.nasa.gov/planets/eph_export.html),
[JPL-compatible binary header](https://www.imcce.fr/content/medias/recherche/equipes/asd/inpop/inpop_file_format_2_0.pdf),
[Astrodienst JPL file distribution](https://www.astro.com/swisseph-download/jplfiles/).


## Bounded batch output

Modification (2026-11-16): `De441::states_at` caps the payload of its returned
`Vec<StateVector>` at **1 MiB** (`MAX_DE441_BATCH_OUTPUT_BYTES`). The state
count limit is derived from the compiled `size_of::<StateVector>()`; callers
can inspect the typed `De441Error::BatchOutputTooLarge` result when the
requested count exceeds it.

The overflow-checked byte calculation occurs before any state evaluation,
coefficient-record I/O, or output-vector allocation. The method does not
truncate, deduplicate, or partially return batches. Accepted results preserve
input order and duplicates; an empty input still validates the supplied TDB
epoch. The budget covers the vector's element payload, not allocator metadata
or the caller-owned input slice.

Synthetic integration tests cover one-below-limit and exact-limit repeated
batches, over-limit rejection before a deliberately missing body series is
evaluated, empty-input epoch validation, and normal propagation of a missing
body series. These tests do not establish real-kernel numerical accuracy or
end-to-end application memory behavior.
