# Experimental provider-backed long-term apparent path — 2026-11-18

**Opt-in research code, not integrated into Mobile or the standard calculation path.** The new `experimental_long_term_apparent_with_provider` uses a caller-provided Rust state provider for each requested TDB epoch. It reuses the existing long-term Vondrák/77-term frame rotation and moving-frame rate, light-time, emission refinement, solar deflection and aberration algorithms; no astronomical algorithm was added to the app. The [predeclared plan](DE441_EXPERIMENTAL_PROVIDER_PLAN_2026-11-18.md) and [prior boundary audit](DE441_MULTIPACK_ORIENTATION_BOUNDARIES_2026-11-18.md) explain the motivation and limits.

The provider supplies barycentric ICRF state/acceleration and the logical half-open coverage containing the converged emission epoch. Requests include Earth reception acceleration, iterative target/observer states, emission target acceleration, and the additional Sun/Earth/target states in the solar-deflection rate stencil (±1/256 TDB day). The frame's ±0.01 TT-day rotation stencil evaluates only the orientation model. The implementation retains provider errors in `ExperimentalProviderApparentError::Provider` even when adapting them through existing solver callbacks; failures never select another model or use overlapping records as an implicit fallback.

Because first-order emission refinement can move a sub-ULP time across a logical handoff, the path **conservatively refuses** a converged emission epoch within `4 * f64::EPSILON * |JD|` of either logical boundary, returning `UnsafeRefinementBoundary`. It also refuses non-finite or inverted provider intervals. This is intentionally stricter than assuming record-aligned physical padding authorizes the neighboring logical pack; refinement exactly at such a handoff is not yet supported even if both packs are installed. A provider must supply honest per-epoch logical coverage and barycentric state metadata. This prototype does not authenticate file contents: the host must verify catalog, byte length and SHA-256 separately.
